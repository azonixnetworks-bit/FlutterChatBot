# Development Rules

1. Read `docs/PROJECT_SPEC.md` before implementing a new phase.
2. Make minimal, phase-scoped changes only.
3. Preserve working code and avoid unrelated refactors.
4. Never commit secrets or expose server-only keys to Flutter.
5. Keep user data strictly isolated in all future data flows.
6. Inspect only files relevant to the requested work.
7. Run relevant tests/analyzers before completing a phase.
8. Stop after the requested phase; do not auto-start the next phase.
